# Test stability notes

- Local API/UI integration smoke tests depend on UI at localhost:4200 and API at localhost:5066 or localhost:7046.
- Keep the Auth0 HTTP interceptor aligned with environment.apiBaseUrl; avoid hardcoded API URLs.
- Demo login credentials documented in school-management-api/docs/frontend-integration.md are useful for frontend smoke tests.
- Tailwind v4 global import should stay in a CSS entry file, not a SCSS global stylesheet, to avoid Sass deprecation warnings during Angular builds.
- Verified Angular UI layout fix: the root app shell must honor route data.hideLayout so auth/login routes render without sidebar/topbar; keep regression coverage for both hidden-layout and standard-layout routes. Guidance references: Angular routing route metadata usage and Angular testing regression coverage.
- Topbar avatar fix: apply explicit fixed width/height on the avatar button itself; avoid percentage sizing inside a forced-size container, which can overflow/misalign toward the lower-right corner.
- Dashboard/API requests must not be globally blocked by Auth0 silent token retrieval; keep Auth0 injection opt-in only, otherwise requests can hang for about 1 minute and never appear in the browser Network tab.
- Angular topbar search enhancement: keep the search field prominent and comfortable with a larger rounded pill, stronger border/shadow, a visible Ctrl+K shortcut hint, and subtle hover/focus motion that respects reduced-motion preferences; preserve the DOM-level regression test added in the topbar component spec.
- Verified Angular global search fix: move dashboard search into the shared topbar, keep the topbar search visible on the home/dashboard route, ensure the shared modal opens reliably from focus, typing, and Ctrl+K, and keep it centered on desktop and top-centered on mobile; regression coverage exists in the topbar and home specs.
- Verified Angular global search list fix: keep each result row padded internally with a full-width flexible button, avoid lateral hover translation and outer outlines/rings that clip inside the modal, and ensure results for queries like "aluno" remain visually contained on desktop and mobile; regression coverage exists in the global search spec.
- Verified Angular services form styling pattern: reuse shared `form-control` and `btn` classes, group actions in a `form-actions` flex row with gap, and place native form fields in a responsive grid for consistent spacing and focus behavior. Guidance references: Angular component styling guide, Angular Tailwind integration guidance, and Tailwind responsive spacing/focus state concepts.
- Verified multi-screen admin layout pattern: use shared helpers in styles.css such as `.page-shell`, `.page-card`, `.page-header`, `.form-grid`, `.field-stack`, and `.form-actions` together with `.form-control` and `.btn` to fix horizontal spacing and native control styling across finance, attendance, assignments, enrollments, reports, and timetabling/calendar pages. References: Angular styling guidance and Tailwind spacing guidance.
- Angular Material admin pages with MDC outlined fields can show a visible middle stripe through the label area; use a shared helper class for outlined fields so the floating label gets a matching background and the notch border segments stay visually normalized. Verified on the calendar/timetabling and notices screens.
- Comunicados screen layout note: use dedicated responsive grid hooks, .notices-form-grid and .notices-filter-grid, with min-width protection and a stronger horizontal gap so Angular Material fields do not get cramped and spacing stays stable.
- Angular Material tabs UX note: when a mat-tab-group would render only one section, replace it with the section content directly or a plain heading instead of a redundant single tab button. Verified on the notices/comunicados screen.
- Admin forms spacing note: use the shared .form-actions--separated helper together with .form-actions to keep reliable vertical spacing between field groups and action buttons across admin forms. Verified on assignments, reports, finance, attendance, notices, timetabling, enrollments, communications manager, class-group copy, and security audit filters.
- Admin action buttons spacing note: if vertical spacing looks inconsistent, check for component-local .form-actions rules overriding the shared global spacing; prefer the shared .form-actions.form-actions--separated pattern and make the global selector specific enough to win. Verified on announcements, documents, students, guardians, assessments, enrollments, communications manager, and import wizard.
- Tailwind cleanup note: when arbitrary-value utilities or page-specific layout rules appear directly in Angular templates, move them into shared helpers in styles.css or component SCSS and keep only semantic hook classes in the markup. Verified on notices, documents, academic-years modal display, and import wizard progress.
- Assessments screen spacing note: unresolved button spacing came from a raw template style block plus local row/action-row layout; fix by removing template styles, using shared .form-grid with .form-actions.form-actions--separated, and keeping page-specific rules in the component SCSS.
- Comunicados spacing note: the issue came from a duplicated legacy create panel in the template; keep only one create panel, define vertical spacing in the component SCSS, and use the shared .form-actions.form-actions--separated button pattern.
- Students page stability note: inconsistent button visuals came from raw utility classes instead of shared .btn variants, and generic user errors like "Erro [object Object]" came from concatenating API error objects; normalize CPF to digits before submit, show the masked CPF format in the UI, and extract nested API messages for user-facing feedback.
- AcademicYears backend test note: CopyAcademicYearUseCase in school-management-api requires ITenantCache<List<AcademicYear>> in its constructor; tests that instantiate this use case must mock ITenantCache<List<AcademicYear>> and pass it explicitly. ITenantCache lives in the SchoolManagement.Application.Services namespace. References consulted in this session: csharp-developer SKILL.md, dotnet-best-practices SKILL.md, copilot-instructions.md.
- Angular unit test runner note: in this workspace, `npm test -- --include ...` still executes the full Karma suite (279 specs) instead of isolating target files; validate targeted specs only after stabilizing baseline suite blockers (for example, portal-register/global-search unrelated failures).
- Angular standalone components with RouterLink in specs require a richer Router mock (`events`, `createUrlTree`, `serializeUrl`) plus ActivatedRoute observables; minimal mocks with only `navigateByUrl` tend to fail at runtime with subscribe/createUrlTree errors.
